{
	Path: ["Configuration"];
	@WString Description: "#p A named @Configuration inside a platform block. Configuration IDs are user-defined; projects commonly use 'Debug' and 'Release', but the schema permits additional names. It overrides values from the surrounding platform and target; property lookup proceeds from Configuration to platform to target to project. Android generation is the exception: it requires exactly two configurations named 'Debug' and 'Release' (case-insensitive) and does not derive them from 'optimization'. It is not a separate platform-specific syntax type.

<code>
#p @windows:
#p {
#p 	@Configuration Debug: { optimization: none; };
#p };
</code>";
};

9:
{
	Path: ["BuildStep"];
	@WString Description: "#p A build action assigned with @BuildStep post_generate, @BuildStep pre_build, or @BuildStep post_build. The 'post_generate' phase runs during reflex generate after project generation; 'pre_build' and 'post_build' are emitted as native build actions. A phase accepts one step or an array of steps and appends to inherited actions by default; use @Unset on the phase ID before replacing them. 'command' is a required argument vector, not a shell command string. The supported fields are 'name', 'command', 'inputs', 'outputs', and 'always_run'. Android generation does not support 'post_build' actions.

<code>
#p @BuildStep pre_build:
#p {
#p 	command: [$qtool$q, $q--prepare$q];
#p 	inputs: $qinput.txt$q;
#p };
</code>";
};
