v0.9.0 — Web MIDI, touch input, and faster downloads

Reflex 0.9.0 brings MIDI input and output to browser audio apps, adds native touch events and optional pinch-to-zoom, and reduces WebAssembly download size with automatic gzip packaging. Web apps also start without a separate audio prompt in the launcher and save preferences while running. The HTTP API now separates status codes from delivery outcomes and lets callers reject a response before processing its headers or body. See [Breaking Changes](../BREAKING_CHANGES.md#v090) before upgrading custom web projects or HTTP clients.

## Changes

### Web audio and input

- Enumerate and enable browser MIDI inputs and outputs through the existing MIDI port APIs. The Bootstrap MIDI panel requests access when opened; custom panels can request it through `request_midi`. MIDI requires a browser with Web MIDI support and permission on HTTPS or localhost. Short MIDI 1.0 messages are supported; SysEx is unavailable.
- Deliver touch contacts through the window client's `OnTouch*` callbacks by default. Set `touchMode: "viewport"` in `startReflex()` to pan and zoom the canvas with two fingers while forwarding single touches to the application.
- Handle initial pointer movement when the cursor is already over the canvas at startup, and normalize wheel distances across pixel, line, and page scroll modes.
- Let the audio backend start or resume browser audio. If autoplay is blocked, the runtime retries on a click or key action on the canvas. Stock launchers no longer show a Start overlay.

### Web builds and runtime

- Gzip-compress deployed `.wasm` files in Debug and Release while keeping the raw linker output for incremental builds. The generated Apache configuration and local server supply the appropriate Wasm and gzip headers, including the decoded size for loading progress.
- Replace `entry_page` with `launch_folder`. Custom HTML, scripts, images, and server configuration can be packaged together. Build timestamps refresh the launcher’s Wasm and runtime entry URLs.
- Pass page query parameters to `System::App::OnStart` as command-line arguments. For example, `?preset=Demo&debug` passes `--preset`, `Demo`, and `--debug`.
- Create the standard temp, user data, and documents folders in browser storage before startup. Support opening absolute HTTP and HTTPS URLs through `System::Open`, subject to browser popup rules.
- Save Bootstrap preferences during ordinary operation in web Debug and Release builds. `File::PersistentPropertySet::Save()` now notifies listeners before encoding the property set.

### HTTP and core

- Pass a `System::HttpConnection::Client` to synchronous requests. The client sees the numeric HTTP status before headers or body data. `Request()` separately reports whether delivery completed, was rejected or aborted by the client, or failed in transport.
- Update the async HTTP wrapper to avoid retrying after a response has been accepted, since callbacks may already hold partial data. The public convenience overload still accepts 2xx responses by default. The VM HTTP binding retains its existing return convention.
- Add `System::ResolvePath()` to resolve an existing path to an absolute path and follow symbolic links on native platforms. On web it checks existence and returns the input path unchanged on success. Resolution failures return an empty string.
- Allow RIFF encoding of `UInt32` properties.

### SDK export and distribution

- Remove the recursive `export.json` exporter and its workflow. SDK exports use `scripts/export_sdk.py` and the root `export_rules.json`; explicit `except` entries can include Git-ignored files.
- Limit the private tag-triggered workflow to library and tool archives. Use the [Public SDK release workflow](../documentation/public_release.md) to assemble, verify, and publish public SDK packages.
